## Resultado esperado

Recuperar após restart sem repetir efeitos incertos. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

agent-runtime recovery; environment-runner job status; GitHub publication port. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Implementar lease de executor e rotina de reconciliação antes de retomar.
- [x] Consultar jobs sobreviventes, hashes de arquivos, commits remotos e PRs conhecidos.
- [x] Reanexar operação em execução ou recuperar resultado; bloquear se não for possível determinar efeito.
- [x] Retomar automaticamente quando política permitir e permissões continuarem válidas.

## Critérios de aceite

- [x] Crash entre escrita e recibo não repete patch cegamente.
- [x] Crash após push ou criação de PR consulta remoto antes de nova tentativa.
- [x] Dois processos recuperando o mesmo run não iniciam dois executores.
- [x] Job ausente não é prova de que comando não executou; resultado incerto exige investigação.

## Validação e evidências exigidas

- [x] Injetar interrupção durante edição, comando, build, push e criação de PR.
- [x] Testar perda do runner, lease vencido, revogação e retomada automática desabilitada.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

recovery_started, operation_reconciled, recovery_blocked, run_resumed.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
