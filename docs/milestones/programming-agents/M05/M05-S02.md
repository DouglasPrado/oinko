# M05-S02 — Navegar com políticas de rede e login de teste

**Status:** pending

**Milestone:** [M05 — Browser isolado e validação funcional](MILESTONE.md)
**Dependências:** [M05-S01](../M05/M05-S01.md)
**Requisitos:** [R02](../REQUIREMENTS.md#r02), [R12](../REQUIREMENTS.md#r12)

## Resultado esperado

Navegar com políticas de rede e login de teste. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

browser network policy; project secrets; dashboard project settings. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Permitir prévias do projeto e documentação pública conforme política de rede.
- [ ] Validar redirects, resolução DNS e cada subrequest para evitar acesso arbitrário à rede privada/host.
- [ ] Guardar credenciais de teste por projeto em cofre; injetar apenas na sessão apropriada.
- [ ] Descrever exceções necessárias para preview interno explicitamente sem abrir toda a LAN.

## Critérios de aceite

- [ ] URL de metadados, localhost do host e rede privada alheia não são navegáveis.
- [ ] Redirecionamento ou DNS rebinding não contorna política.
- [ ] Login de teste não aparece nos prompts, eventos ou sessão de docs.
- [ ] Permissões revogadas encerram acesso futuro da sessão.

## Validação e evidências exigidas

- [ ] Testar redirects, IPv4/IPv6, subresources, rebinding e preview autorizado.
- [ ] Testar login de dois projetos e documentação que tenta acessar serviço privado.
- [ ] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [ ] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

browser_navigation_allowed, browser_navigation_denied, test_credential_used; sem valor secreto.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
