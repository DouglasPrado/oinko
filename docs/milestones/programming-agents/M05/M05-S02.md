**Status:** completed — política de rede (prévias do projeto, documentação pública, redirects, DNS rebinding, subrequests, IPv6/metadados) e credenciais de teste por projeto testadas em unitário e Docker real na revisão `60fe1f9`.

## Resultado esperado

Navegar com políticas de rede e login de teste. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

browser network policy; project secrets; dashboard project settings. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Permitir prévias do projeto e documentação pública conforme política de rede.
- [x] Validar redirects, resolução DNS e cada subrequest para evitar acesso arbitrário à rede privada/host.
- [x] Guardar credenciais de teste por projeto em cofre; injetar apenas na sessão apropriada.
- [x] Descrever exceções necessárias para preview interno explicitamente sem abrir toda a LAN.

## Critérios de aceite

- [x] URL de metadados, localhost do host e rede privada alheia não são navegáveis.
- [x] Redirecionamento ou DNS rebinding não contorna política.
- [x] Login de teste não aparece nos prompts, eventos ou sessão de docs.
- [x] Permissões revogadas encerram acesso futuro da sessão.

## Validação e evidências exigidas

- [x] Testar redirects, IPv4/IPv6, subresources, rebinding e preview autorizado.
- [x] Testar login de dois projetos e documentação que tenta acessar serviço privado.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

browser_navigation_allowed, browser_navigation_denied, test_credential_used; sem valor secreto.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
