# M05-S01 — Provisionar browser isolado por execução

**Status:** pending

**Milestone:** [M05 — Browser isolado e validação funcional](MILESTONE.md)
**Dependências:** [M00-S02](../M00/M00-S02.md), [M01-S03](../M01/M01-S03.md), [M03-S01](../M03/M03-S01.md)
**Requisitos:** [R02](../REQUIREMENTS.md#r02), [R12](../REQUIREMENTS.md#r12)

## Resultado esperado

Provisionar browser isolado por execução. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

packages/environments; apps/environment-runner; browser image. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Criar container de browser gerenciado pelo runner com Chromium/Playwright em versões compatíveis e fixadas.
- [ ] Executar como não root com sandbox do Chromium habilitada, recursos e lifecycle explícitos.
- [ ] Criar sessão por run e separar contexto de documentação do contexto autenticado de testes.
- [ ] Limpar processos e dados de sessão no término, mantendo apenas artefatos pela política.

## Critérios de aceite

- [ ] Dois runs não compartilham cookies/storage/downloads.
- [ ] Container não recebe Docker socket, perfil pessoal nem credenciais do host.
- [ ] Crash e cancelamento encerram sessões órfãs e preservam metadados de evidência.
- [ ] Indisponibilidade de browser bloqueia check funcional de forma explícita.

## Validação e evidências exigidas

- [ ] Testar container real, compatibilidade de versão, crash e cleanup.
- [ ] Testar isolamento de sessões entre dois bots no mesmo projeto.
- [ ] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [ ] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

browser_session_created, browser_session_closed, browser_session_failed.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
