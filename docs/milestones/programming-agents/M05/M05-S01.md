# M05-S01 — Provisionar browser isolado por execução

**Status:** completed — imagem fixada, não root com sandbox do Chromium, sessão por bot/run, isolamento de cookies/storage, crash, órfãos, ociosidade (Docker real) e fechamento das sessões ao concluir e ao cancelar o run testados.

**Milestone:** [M05 — Browser isolado e validação funcional](MILESTONE.md)
**Dependências:** [M00-S02](../M00/M00-S02.md), [M01-S03](../M01/M01-S03.md), [M03-S01](../M03/M03-S01.md)
**Requisitos:** [R02](../REQUIREMENTS.md#r02), [R12](../REQUIREMENTS.md#r12)

## Resultado esperado

Provisionar browser isolado por execução. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

packages/environments; apps/environment-runner; browser image. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Criar container de browser gerenciado pelo runner com Chromium/Playwright em versões compatíveis e fixadas.
- [x] Executar como não root com sandbox do Chromium habilitada, recursos e lifecycle explícitos.
- [x] Criar sessão por run e separar contexto de documentação do contexto autenticado de testes.
- [x] Limpar processos e dados de sessão no término, mantendo apenas artefatos pela política.

## Critérios de aceite

- [x] Dois runs não compartilham cookies/storage/downloads.
- [x] Container não recebe Docker socket, perfil pessoal nem credenciais do host.
- [x] Crash e cancelamento encerram sessões órfãs e preservam metadados de evidência.
- [x] Indisponibilidade de browser bloqueia check funcional de forma explícita.

## Validação e evidências exigidas

- [x] Testar container real, compatibilidade de versão, crash e cleanup.
- [x] Testar isolamento de sessões entre dois bots no mesmo projeto.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

browser_session_created, browser_session_closed, browser_session_failed.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
