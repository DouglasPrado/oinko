## Resultado esperado

Vincular preview e verificação funcional à revisão. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

preview service; validation orchestrator; dashboard evidence. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Associar preview à worktree/commit ou hash de árvore e registrar configuração do ambiente.
- [x] Orquestrar reproduzir problema → editar → CLI → preview → validar fluxo.
- [x] Coletar screenshot, passos, console/rede e resultado por critério.
- [x] Invalidar evidência se código ou configuração relevante mudar.

## Critérios de aceite

- [x] Preview healthy não é confundido com fluxo funcional aprovado.
- [x] Teste visual/funcional indica URL, revisão, viewport e pré-condições.
- [x] Falha de build, healthcheck ou browser fica ligada ao passo correto.
- [x] Dashboard exibe artefatos e Telegram entrega resumo e link autorizado.

## Validação e evidências exigidas

- [ ] Executar mudança visual real e formulário com erro intencional.
- [x] Rebuild em outra revisão e garantir que evidência antiga não aprove a nova.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

preview_started, preview_ready, preview_failed, functional_check_finished, evidence_invalidated.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
