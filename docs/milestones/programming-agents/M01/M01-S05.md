## Resultado esperado

Explorar uma execução na telemetria. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

apps/dashboard/features/telemetry; serviços de consulta compartilhados; MCP. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Exibir árvore bot → projeto → tarefa → run → passo com linha do tempo e filtros.
- [ ] Ligar decisões, chamadas, resultados, diffs e artefatos; mostrar estados uncertain e lacunas.
- [x] Adicionar consulta paginada por API/MCP, retornando resumos e referências em vez de payload ilimitado.
- [x] Distinguir planejado, executado, testado, publicado em draft e aceito pelo usuário.

## Critérios de aceite

- [ ] Um operador consegue explicar por que uma tarefa ficou bloqueada e localizar a operação responsável.
- [x] Bot sem permissão não acessa runs por adivinhação de ID.
- [ ] Navegação mobile funciona e suporta eventos chegando enquanto página está aberta.
- [x] Metadados continuam úteis com captura none e artefatos expirados.

## Validação e evidências exigidas

- [x] Testar E2E com execução sintética completa, falha e retomada.
- [ ] Testar paginação sem duplicação, isolamento e carregamento de run grande.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

telemetry_query, artifact_accessed; não armazenar corpo sensível dos filtros.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
