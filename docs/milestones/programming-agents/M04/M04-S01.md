## Resultado esperado

Configurar capacidades e políticas na dashboard. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

apps/dashboard bot/project settings; shared configuration service. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Criar configuração reutilizável de programação, retomada, autonomia e modelos por bot.
- [ ] Configurar comandos por pacote, browser e repositórios por projeto.
- [ ] Mostrar política efetiva, origem e necessidade de reinício quando aplicável.
- [x] Validar schema no serviço compartilhado usado por UI e MCP.

## Critérios de aceite

- [x] Criar segundo bot exige configuração, sem copiar implementação.
- [x] Permissões e capacidades são visíveis antes de iniciar trabalho.
- [x] Não há campo de teto financeiro aplicado por padrão ou implícito.
- [x] Salvar configuração inválida não altera parcialmente o bot.

## Validação e evidências exigidas

- [x] Testar E2E criação/configuração de dois bots e round-trip via serviço.
- [x] Testar alterações concorrentes e resumo de políticas efetivas.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

bot_configuration_changed, project_configuration_changed; diff redigido e ator.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
