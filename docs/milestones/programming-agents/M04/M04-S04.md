## Resultado esperado

Expor controle e consulta no MCP Oinko. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

packages/mcps/oinko; shared services; tool registry. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Expor iniciar/listar/consultar/controlar runs e consultar evidências com schemas paginados.
- [ ] Reutilizar update de bots para novas capacidades e configurar projeto com revisão esperada.
- [ ] Usar mesmos serviços, autorização e idempotência de dashboard/runtime.
- [ ] Detectar equivalência de ferramentas internas e MCP para não carregar duas cópias no modelo.

## Critérios de aceite

- [ ] MCP administra qualquer bot autorizado e nunca assume bot dev.
- [ ] Resposta de iniciar informa runId, status e meio de acompanhar, sem bloquear até terminar.
- [ ] MCP conectado a bot não herda privilégios administrativos da instalação.
- [ ] Ferramentas selecionadas pelo Jev continuam sujeitas à autorização no executor.

## Validação e evidências exigidas

- [ ] Testar contrato MCP real, round-trip de configuração e permissão negada.
- [ ] Comparar resultados de operação equivalente via UI, canal e MCP.
- [ ] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [ ] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

mcp_call_started, mcp_call_finished com runId e operationId; deduplicação de spans.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
