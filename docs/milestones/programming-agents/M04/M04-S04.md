## Resultado esperado

Expor controle e consulta no MCP Oinko. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

packages/mcps/oinko; shared services; tool registry. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Expor iniciar/listar/consultar/controlar runs e consultar evidências com schemas paginados.
- [x] Reutilizar update de bots para novas capacidades e configurar projeto com revisão esperada.
- [x] Usar mesmos serviços, autorização e idempotência de dashboard/runtime.
- [x] Detectar equivalência de ferramentas internas e MCP para não carregar duas cópias no modelo.

## Critérios de aceite

- [x] MCP administra qualquer bot autorizado e nunca assume bot dev.
- [x] Resposta de iniciar informa runId, status e meio de acompanhar, sem bloquear até terminar.
- [x] MCP conectado a bot não herda privilégios administrativos da instalação.
- [x] Ferramentas selecionadas pelo Jev continuam sujeitas à autorização no executor.

## Validação e evidências exigidas

- [x] Testar contrato MCP real, round-trip de configuração e permissão negada.
- [x] Comparar resultados de operação equivalente via UI, canal e MCP.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

mcp_call_started, mcp_call_finished com runId e operationId; deduplicação de spans.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
