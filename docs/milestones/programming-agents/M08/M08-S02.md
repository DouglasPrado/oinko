## Resultado esperado

Diagnosticar gargalos a partir da telemetria. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

analytics service; dashboard comparisons; MCP reports. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Agregar conclusão, falhas por etapa, intervenção humana, tempo, tokens e custo por tarefa concluída.
- [x] Classificar regressões de contexto, modelo, ferramenta, ambiente, testes e publicação.
- [x] Permitir comparação por bot/projeto/política/modelo com amostra e cobertura.
- [x] Gerar propostas de melhoria com hipótese, casos afetados e evidência, sem alterá-las automaticamente.

## Critérios de aceite

- [x] Relatório distingue correlação de causalidade e informa amostra insuficiente.
- [x] Custo por concluída inclui também esforço das tentativas falhas no mesmo conjunto.
- [x] Execução rápida que falha critérios não é classificada melhor.
- [x] Operador navega do agregado até traces autorizados que o sustentam.

## Validação e evidências exigidas

- [x] Testar agregação com sucesso, falha, intervenção e custo indisponível.
- [x] Conferir cálculos com dataset pequeno cujo resultado é conhecido.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

improvement_opportunity_detected, evaluation_comparison_created.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
