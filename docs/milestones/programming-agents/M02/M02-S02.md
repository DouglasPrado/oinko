# M02-S02 — Ler intervalos com versão de conteúdo

**Status:** completed — leitura por intervalo com hash, limites, continuação, Unicode/CRLF, erros explícitos e estimativa de tokens da leitura testados em unitário, simulado e Docker real; não depende de sistema externo.

**Milestone:** [M02 — Entendimento do projeto e edição precisa](MILESTONE.md)
**Dependências:** [M02-S01](../M02/M02-S01.md)
**Requisitos:** [R09](../REQUIREMENTS.md#r09), [R14](../REQUIREMENTS.md#r14)

## Resultado esperado

Ler intervalos com versão de conteúdo. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

operações de arquivo no runner; schemas de ferramentas. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Ler intervalos de linhas com números, versão/hash e tamanho total.
- [x] Devolver limites aplicados e referência para continuação.
- [x] Tratar encoding, arquivo ausente e binário com erro explícito.
- [x] Aplicar limite de resposta sem usar corte como se fosse arquivo completo.

## Critérios de aceite

- [x] Arquivo maior que 200 KB pode ser inspecionado em partes sem leitura integral no contexto.
- [x] Hash identifica exatamente o conteúdo observado para edição posterior.
- [x] Limites e linhas são consistentes com Unicode e arquivo sem newline final.
- [x] Leitura não revela caminhos do host nem arquivos externos à raiz.

## Validação e evidências exigidas

- [x] Testar arquivo grande, Unicode, CRLF, linhas vazias e ranges inválidos.
- [x] Comparar paginação com conteúdo esperado e registrar tokens de entrada.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

workspace_read; path relativo, range, hash, bytes retornados e truncamento.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
