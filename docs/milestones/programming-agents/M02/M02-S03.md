# M02-S03 — Substituição exata e patch com validação prévia

**Status:** pending

**Milestone:** [M02 — Entendimento do projeto e edição precisa](MILESTONE.md)
**Dependências:** [M02-S02](../M02/M02-S02.md), [M01-S02](../M01/M01-S02.md)
**Requisitos:** [R08](../REQUIREMENTS.md#r08), [R09](../REQUIREMENTS.md#r09)

## Resultado esperado

Substituição exata e patch com validação prévia. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

runner file service; contratos de edição; SDK adapters. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Implementar replace exato com expectativa de hash e unicidade.
- [ ] Implementar patch multifile validando todos os alvos antes de escrever.
- [ ] Serializar mutações da mesma worktree, journalizar antes/depois e detectar interferência externa.
- [ ] Preservar mudanças anteriores; recuperar escrita parcial após crash sem restaurar conteúdo alheio.

## Critérios de aceite

- [ ] Conteúdo stale ou correspondência ambígua produz conflito sem escrita.
- [ ] Falha de validação em qualquer arquivo evita iniciar o lote inteiro.
- [ ] Crash no meio não é tratado como atomicidade completa; recibo identifica arquivos aplicados e pendentes.
- [ ] Patch não escapa por path ou symlink e não reseta alterações preexistentes.

## Validação e evidências exigidas

- [ ] Testar patch válido/inválido, criação/remoção autorizada, Unicode e conflito simultâneo.
- [ ] Interromper após primeira escrita e reconciliar hashes; testar arquivo alterado por usuário durante recuperação.
- [ ] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [ ] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

workspace_edit_intended, workspace_edit_finished, workspace_edit_conflict, operation_uncertain.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
