## Resultado esperado

Definir políticas por bot, projeto e execução. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

packages/bots/schema; packages/workspaces; portas de autorização. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Criar schema de capacidades, autonomia, retomada e roteamento por bot.
- [x] Configurar repositórios, comandos de validação, ambiente e credenciais de teste por projeto.
- [x] Resolver configuração efetiva versionada por run e conferir permissões novamente em cada operação.
- [x] Documentar defaults: um run ativo por bot, retomada automática, PR draft autorizado, nenhum teto financeiro.

## Critérios de aceite

- [x] Configuração do Dev não se torna default obrigatório de outros bots.
- [x] Um bot sem acesso ao projeto não consegue listar arquivos, traces, artefatos ou publicar por outra interface.
- [x] Alterações de política não mudam silenciosamente um run já iniciado; revogações de acesso têm efeito imediato.
- [x] Merge, deploy e operações destrutivas exigem autorização explícita vinculada à operação; não há bloqueio por gasto acumulado.

## Validação e evidências exigidas

- [x] Testar matriz de dois bots e dois projetos por API, canal e MCP.
- [x] Testar revogação durante execução e validação de configuração inválida.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

policy_resolved, permission_checked, permission_denied; registrar versão e motivo sem segredos.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
