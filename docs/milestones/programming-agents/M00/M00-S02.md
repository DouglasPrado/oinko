# M00-S02 — Definir políticas por bot, projeto e execução

**Status:** pending

**Milestone:** [M00 — Contratos compartilhados e linha de base](MILESTONE.md)
**Dependências:** [M00-S01](../M00/M00-S01.md)
**Requisitos:** [R01](../REQUIREMENTS.md#r01), [R02](../REQUIREMENTS.md#r02), [R04](../REQUIREMENTS.md#r04), [R05](../REQUIREMENTS.md#r05), [R14](../REQUIREMENTS.md#r14)

## Resultado esperado

Definir políticas por bot, projeto e execução. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

packages/bots/schema; packages/workspaces; portas de autorização. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Criar schema de capacidades, autonomia, retomada e roteamento por bot.
- [ ] Configurar repositórios, comandos de validação, ambiente e credenciais de teste por projeto.
- [ ] Resolver configuração efetiva versionada por run e conferir permissões novamente em cada operação.
- [ ] Documentar defaults: um run ativo por bot, retomada automática, PR draft autorizado, nenhum teto financeiro.

## Critérios de aceite

- [ ] Configuração do Dev não se torna default obrigatório de outros bots.
- [ ] Um bot sem acesso ao projeto não consegue listar arquivos, traces, artefatos ou publicar por outra interface.
- [ ] Alterações de política não mudam silenciosamente um run já iniciado; revogações de acesso têm efeito imediato.
- [ ] Merge, deploy e operações destrutivas exigem autorização explícita vinculada à operação; não há bloqueio por gasto acumulado.

## Validação e evidências exigidas

- [ ] Testar matriz de dois bots e dois projetos por API, canal e MCP.
- [ ] Testar revogação durante execução e validação de configuração inválida.
- [ ] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [ ] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

policy_resolved, permission_checked, permission_denied; registrar versão e motivo sem segredos.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.

## Registro de entrega

- Implementação/PR: pendente.
- Revisão e ambiente testados: pendente.
- Evidências automatizadas: pendente.
- Evidências reais / aceite de operador: pendente ou não aplicável com justificativa.
- Limitações e riscos residuais: pendente.
- Não alterar para concluída apenas porque código compilou ou testes simulados passaram.
