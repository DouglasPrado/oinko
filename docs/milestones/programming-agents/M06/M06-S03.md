# M06-S03 — Criar ou atualizar draft PR sem duplicação

**Status:** pending

**Milestone:** [M06 — GitHub App e entrega automática em draft](MILESTONE.md)
**Dependências:** [M06-S02](../M06/M06-S02.md), [M03-S04](../M03/M03-S04.md)
**Requisitos:** [R05](../REQUIREMENTS.md#r05), [R08](../REQUIREMENTS.md#r08), [R13](../REQUIREMENTS.md#r13)

## Resultado esperado

Criar ou atualizar draft PR sem duplicação. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

GitHub API adapter; run publication records; MCP. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Definir identidade bot/projeto/task/repo e run originador para um PR reaproveitável por trabalho.
- [ ] Publicar branch da tarefa e criar draft com problema, mudanças, testes, preview e pendências.
- [ ] Consultar referência remota e PR existente após timeout antes de repetir efeito.
- [ ] Vincular PRs separados quando tarefa envolver múltiplos repositórios.

## Critérios de aceite

- [ ] Retry após criação remota com resposta perdida encontra o PR e não abre outro.
- [ ] Nova execução na mesma tarefa atualiza PR aberto compatível; PR fechado/merged exige decisão registrada.
- [ ] PR permanece draft e não é marcado como mergeado ou aprovado.
- [ ] Mensagem final lista links e validações reais, incluindo skipped/pendências.

## Validação e evidências exigidas

- [ ] Testar timeout antes/depois de push e de create PR.
- [ ] Executar fluxo real com dois repos de teste e garantir idempotência.
- [ ] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [ ] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

pull_request_reconciled, draft_pull_request_created, draft_pull_request_updated, publication_blocked.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.

## Registro de entrega

- Implementação/PR: pendente.
- Revisão e ambiente testados: pendente.
- Evidências automatizadas: pendente.
- Evidências reais / aceite de operador: pendente ou não aplicável com justificativa.
- Limitações e riscos residuais: pendente.
- Não alterar para concluída apenas porque código compilou ou testes simulados passaram.
