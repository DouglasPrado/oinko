# M06-S01 — Conectar GitHub App e instalações por projeto

**Status:** in_progress — App própria, chave cifrada fora do banco, tokens mínimos por repositório e diagnósticos testados com API GitHub simulada; instalação real em repositório de teste pendente e a UI não distingue instalado de acessível.

**Milestone:** [M06 — GitHub App e entrega automática em draft](MILESTONE.md)
**Dependências:** [M00-S02](../M00/M00-S02.md), [M01-S03](../M01/M01-S03.md), [M04-S01](../M04/M04-S01.md)
**Requisitos:** [R02](../REQUIREMENTS.md#r02), [R05](../REQUIREMENTS.md#r05), [R13](../REQUIREMENTS.md#r13)

## Resultado esperado

Conectar GitHub App e instalações por projeto. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

integration service; encrypted secret store; dashboard Integrations. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [x] Configurar GitHub App própria da instância e selecionar instalações/repositórios permitidos.
- [x] Guardar chave privada cifrada com chave mestra fora do banco e de logs; documentar rotação/backup.
- [x] Emitir tokens curtos limitados à instalação/repo, com Contents e PR write e checks/status read.
- [x] Diagnosticar instalação revogada, permissão insuficiente e expiração sem pedir PAT pessoal.

## Critérios de aceite

- [x] Somente repos explicitamente vinculados podem receber push/PR.
- [x] Chave e token não aparecem em resposta MCP, diff de configuração ou ambiente do agente.
- [x] Permissões adicionais só são solicitadas para recurso que as exija.
- [ ] UI distingue integração instalada de acesso efetivamente válido ao repo.

## Validação e evidências exigidas

- [x] Testar API simulada, rotação, token expirado e instalação removida.
- [ ] Validar instalação real em repositório de testes e acesso negado a outro repo.
- [x] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [x] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

github_installation_checked, github_token_issued, github_permission_denied; somente identificadores.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
