## Resultado esperado

Isolar publicação autenticada e revisar conteúdo. A capacidade pertence à plataforma e deve funcionar com qualquer bot autorizado.

## Áreas previstas

publication service/container; Git runner; shared authorization. Caminhos definitivos serão confirmados na implementação; são áreas de responsabilidade, não arquivos já entregues.

## Trabalho a construir

- [ ] Executar Git autenticado em processo/container de publicação separado do terminal do agente.
- [ ] Transmitir conteúdo/revisão revisados sem executar hooks, helpers ou comandos definidos pelo repositório com credenciais.
- [ ] Conferir base, arquivos incluídos, segredos, diff e checks da revisão exata antes do commit/push.
- [ ] Preservar mudanças externas e impedir force push automático.

## Critérios de aceite

- [ ] Código de projeto não lê token por processo, arquivo, Git config ou log.
- [ ] Mudança entre revisão e push interrompe publicação e exige nova checagem.
- [ ] Erro de conflito remoto é apresentado sem reset/force push.
- [ ] Publicação aplica política snapshot e permissões atuais; merge/deploy não fazem parte da operação.

## Validação e evidências exigidas

- [ ] Testar hook/helper malicioso, arquivo alterado depois da revisão e conflito remoto.
- [ ] Verificar isolamento de credenciais com comando executado no sandbox em paralelo.
- [ ] Aplicar os gates comuns de [validação](../VALIDATION.md), registrando comando, revisão, resultado e limitações.
- [ ] Executar verificações negativas de permissão pertinentes; comprovar ausência de dependência de ID/nome do bot.

## Telemetria obrigatória

publication_reviewed, git_commit_created, git_push_started, git_push_finished.

Aplicar o [contrato transversal](../TELEMETRY.md): correlação, versão efetiva, tentativas, duração, resultado/erro, redaction, acesso e retenção. Para operações com efeito, persistir intenção e recibo; resultado incerto deve ser reconciliado. Testes devem consultar os eventos persistidos, não apenas verificar que um callback foi chamado.

## Falhas e compatibilidade

Usar os estados e regras de [arquitetura](../ARCHITECTURE.md). Falhas mantêm evidência, não ampliam permissões nem apagam trabalho do usuário. Interfaces existentes continuam compatíveis; ativação segue capacidade/política do bot e do projeto.
